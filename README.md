# 開発の流れ
GitHubを使って協力し、効率的に開発を進めていく流れを示します。ここではCUIを基準に説明していますが、GitHub Desktopやその他ツールを利用する場合は、適宜読み替えてください。
hogehogeg
## 1. リポジトリのクローン

まずはGitHub上のリポジトリをローカルにクローン(コピーすることとほぼ同義)します。
以下のコマンドを使用してください。

 ``` git clone https://github.com/Code-Dumper/Bakuha-DBldg.git ```
 これにより、ローカル環境にリポジトリのコピーが作成されます。

 ## 2.新しいブランチの作成

作業内容を独立して管理するため、作業ごとに新しいブランチを作成します。

 ``` git checkout -b feature-[機能名] ```
 
 例：「ログイン機能」を実装する場合
 ```git checkout -b feature-login```
 基本的には、mainブランチには直接変更を加えず、必要な機能ごとにブランチを作成して作業をしてください(完成してしまっているものについては一つのPRで出してしまって結構です)  
マージ(後述)が完了したブランチは削除するのが一般的です。

 ## 3.コードを編集

 作成したブランチ内で、担当するタスクに関連するコードを編集します。  
 編集後は以下の手順で変更をコミットしてください。 
 
```
git add .
```

続いて、次のコマンドによりコミットを実行します。
```
git commit -m "Add login functionality"
```
コミットメッセージは変更内容がわかりやすいよう、簡潔で具体的に書くようにしましょう(推奨事項、例えば問題の共有に便利)

## 4.変更をGitHubにプッシュ
ローカルでコミットした変更をGitHubに反映させます。
``` git push origin feature-[機能名] ```

## 5.Pull Requestを作成
GitHub上でPull Request（PR）を作成し変更内容をレビュー依頼します。


・プロジェクトページ(https://github.com/Code-Dumper/Bakuha-DBldg)にアクセスする。  
・「Pull Requests」タブを押す。  
・新しいPRを作成(New Pull Request)。  
・必要な情報（変更内容や目的）を記入し、レビュアーに自分(または不安なときは他人)を指定して送信。

PRの説明には次の情報を適宜記載するのがおすすめです。
・目的(変更がなぜ必要か)、内容(具体的に何をこのコードは実装するのか)、テスト結果(必要であれば)
(実際、数万行のコードを読む際に、コードの目的やコメント、メモがないと、たとえコードが動いたとしても、リファクタリング(同じ機能を他のコードで実装すること)する際や、コードをレビューする際に手間が増えます。時間がかかります。もったいないです。)


## 6. コードレビューとマージ

PRが作成されたら、担当のレビュアーがコードをチェックします。(自分に設定したなら自分でOKを出します)
問題がなければ、マージして作業が完了します。

マージは、レビューが終わったコードをメインブランチに統合することです。

## 7. 最新のコードを取得
メインブランチに誰かのPRのマージなどで新しい変更が加わった場合、定期的にローカルに取り込んでください。
``` git pull origin main ```
競合が発生した場合は、その内容を確認し、適切に解決してください。

## 8 再度、作業を繰り返す
新たな作業が発生した場合は、再度新しいブランチを作成して同様の手順で作業を進めます。

一見めんどくさそうに見える流れですが、こうすることにより、大量の人が作業する際にも効率よく、わかりやすく、協力して作業することができます。(何なら、この技術を身につけて、完全在宅で仕事することも環境によっては可能です)

## コードの可読性についての推奨事項
# 1. コメントを適切に書く
必要な箇所や、意味が明確でないところにはコメントを書きましょう。
```Java
//タイマーの情報と現在地点の情報を提供するクラス。タイマーの情報や現在位置をViewに伝える必要があるため、
//こいつはObservableの性質を持っていなければならない。
public class GameState{
 private String currentPanel;
 private boolean isPaused;
 private int remainingTime;
 private boolean isTimerRunning;
 ...
}
```
# 2.命名規則を統一する。
・変数名や関数名は意味がわかるものにしましょう。  
・例：user_dataやprocess_orderなど。

# 3.不要なコードは削除する
・不要なコードは削除してください。

# 4.インデントやフォーマットを整える。
・おそらく当たり前なので省略します。
